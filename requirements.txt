# Mercury's dependencies: the AUTHORED input (Phase 4 section 8.2; the operator, 2026-10-09).
#
# One line per distribution the code or the suite imports, pinned at the version the
# deployment host runs. requirements.lock is COMPILED from this file and
# requirements-overrides.txt, on the laptop, never by hand:
#
#   uv pip compile requirements.txt --override requirements-overrides.txt \
#     --generate-hashes --python-version 3.12 \
#     --python-platform x86_64-unknown-linux-gnu -o requirements.lock
#
# With -o naming the existing lock, uv keeps its pins unless something forces a move;
# `--upgrade-package <name>` moves one. CI installs the lock as the host does
# (--require-hashes --no-deps) and tests it; the host's virtualenv is built from it
# (section 8.3). A new dependency is a line here and the command above, nothing else.
#
# The first lock (2026-10-09) is exactly the 70 versions the host ran from apt and pip:
# the first venv changes where the libraries live, not which versions. The first ordinary lock
# change ADDS networkx and moves nothing else (2026-10-10). The next takes the three overrides
# off (textfsm 1.1.3, future, pycparser), on their own, one variable at a time, and pip check
# must come back clean after it (the operator, 2026-10-10). colorama is dropped in a change of
# its own.
