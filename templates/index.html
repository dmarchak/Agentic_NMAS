NetBox (Source of Truth)

Loading… Open NetBox ↗

NetBox is the intended source of truth for inventory; this tab is the opposite direction — a one-way discovery import that pushes what NMAS already knows into NetBox, so a hand-curated NetBox is exactly what the write gate below exists to protect. Each device list is mirrored as a NetBox region (with a same-named site beneath it). Each device's model, serial number, platform and software version are read from its saved golden config — no SSH session is opened — and its IPv4 interface addresses are pushed into NetBox IPAM as prefixes and IP addresses assigned to DCIM interfaces, with the management IP set as the device's primary IPv4.

NetBox is not configured

To use this tab, enter your NetBox server URL and API token in Settings. The API token must be a NetBox API key (see Admin → API Tokens in NetBox). This app authenticates using the Authorization: Bearer <token> header NetBox's own REST API docs recommend, and falls back to Token <token> for older NetBox versions.

Import to NetBox (discovery)

Importing reads each device's saved golden config and writes the results into NetBox DCIM + IPAM; each list becomes its own region. It opens no SSH session, so an offline device is still imported provided it has a golden config — what gets skipped is a device with no golden config saved, reported with that reason. The one part that needs a live session is CDP/LLDP neighbour discovery, attempted only for devices already known to be online.

You will see a read-only preview of every object to be created or updated before anything is written, and confirming is one-shot. Objects NMAS creates are tagged nmas-managed and recorded in its own created-object list; Remove deletes only what appears in both, so a region, site, VRF or device a human curated is reported as skipped rather than deleted.
